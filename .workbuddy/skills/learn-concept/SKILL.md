# learn-concept · Source-Traced Concept Guide 生成 Skill

## 1. 这个 Skill 解决什么问题

把"我想学 X,但不知道哪些是权威说法、哪些是 AI 编的、学了之后怎么用"这个问题流程化。

- 为每个概念输出一份**来源可追溯(Source-Traced)**的指南:每个核心论断都带 `[S1][S2]` 式引用,来源表分级可查。
- 采用**编号章节 + 元信息标签 + 可视化图表 + 策略卡片 + 交互练习 + 自测题**的统一结构,让不同概念之间可横向比较。
- 把**易混淆点**、**使用边界**和**工程最佳实践**当一等公民处理,避免"读完感觉懂了,实际分不清 X / Y / Z"。

## 2. 输入

调用方需向 Skill 提供以下信息(尽量一次给齐,缺什么我会问):

| 字段              | 必填 | 说明                                                              |
| ----------------- | ---- | ----------------------------------------------------------------- |
| `concept`         | 是   | 待学概念的标准中文名,必要时附英文/缩写                          |
| `known`           | 否   | 学习者已有的先验(0 / 入门 / 已了解相邻概念)                     |
| `goal`            | 否   | 学习目标(面试 / 写代码 / 写论文 / 和同学讲清 / 工程落地……)      |
| `deadline`        | 否   | 截止时间,影响卡片深度                                            |
| `preferred_form`  | 否   | 输出形态:HTML 卡片(默认)/ Markdown 摘要 / 极简一句话              |
| `extra_context`   | 否   | 一段课程讲义、论文摘要、官方文档片段等;若不提供则全靠模型常识  |

可被其他流程复用:传入 `concept` 字符串即可重跑,无需修改 Skill 本体。

## 2.5 资料来源标准(硬性)

### 2.5.1 来源分级

| 等级 | 性质 | 典型来源 | 使用方式 |
|------|------|----------|----------|
| **T0 一手 / 学术** | 同行评审论文、arXiv 预印本(作者来自知名机构)、会议论文集(NeurIPS/ICML/ICLR/ACL/EMNLP)、官方标准文档 | arxiv.org/abs/xxx、ACL Anthology、IEEE、ACM、OpenAI/Anthropic/Google 官方技术报告 | 优先引用,用于支撑核心机制、关键结论和数字 |
| **T1 权威转述** | 厂商官方文档、厂商工程博客、知名研究机构博客、权威书籍 / 教材章节 | docs.anthropic.com、openai.com/research、research.google、distill.pub、Lilian Weng 博客 | 用于解释工程实践、产品形态、官方定义 |
| **T2 背景佐证** | 维基百科、科普文章、社区总结 | wikipedia.org、medium/掘金等技术社区 | 仅用于辅助理解,**不能**替代 T0/T1 作为核心来源 |

### 2.5.2 最低数量与质量要求

每份概念卡片必须满足:
- **≥ 2 个 T0 来源**(至少一篇支撑核心机制,一篇支撑边界/对比/最新进展)。
- **≥ 1 个 T1 来源**(官方文档或厂商/研究机构的权威解读)。
- **≥ 1 个 2023 年及以后的来源**(对 AI 类概念,确保内容不过时;若是经典理论如 CAP/Transformer 可放宽,但需说明)。
- 总来源数建议 6–10 条;Wikipedia 最多 1 条,且只能标 T2。
- **对关键术语必须给出权威定义**:优先引用官方文档或开创性论文,不能只用通俗解释。例如:上下文窗口要同时给出 LangGraph 的"最大 token 数"定义和 Anthropic 的"采样时实际包含的 token 集合"定义。

### 2.5.3 推荐检索路径

按优先级依次查:
1. **arXiv**:`https://arxiv.org/search/?query=<英文概念>&searchtype=all&source=header&order=-announced_date_first`
2. **ACL Anthology**:适用于 NLP / LLM 相关概念
3. **Google Scholar**:找高被引论文和最新综述
4. **厂商官方文档 / 研究博客**:Anthropic、OpenAI、Google DeepMind、Microsoft Research
5. **GitHub 官方仓库 / 论文实现**:验证方法是否存在
6. **source-tracer skill**(若可用):自动追溯原始出处

## 3. 工作流程(Skill 被调用后必须按序执行)

1. **拆解输入**
   - 把概念拆成 3–5 个"如果不懂这些就看不懂 X"的子问题(下文称 §2 核心问题)。
   - 若 `known` 给出"入门",跳过基础解释,直入差异与边界。

2. **查证与建源**
   - 对每个子问题,优先按 §2.5 的 T0 → T1 → T2 顺序找来源。
   - **不能引用二手博客当一手源**;Wikipedia / 官方文档 / arXiv 摘要 / 标准组织页面 才可作 T0。
   - 对 AI 类概念,必须找到 2023 年后的进展(长上下文、新架构、产品化实践、Agent 最佳实践等),不能只停留在 2022 年甚至更早。
   - 对核心术语,必须找到**至少两个权威定义**并对比,说明它们强调的不同侧面。
   - 实在查不到时,在卡片里**显式标注"未核验 - 仅作背景"**,装作权威的做法要禁止。

3. **组织输出**
   - 按 §4 的固定结构生成,**栏目顺序固定**;任何栏目都不能省,缺资料时写"待补 - 来源缺失",直接删栏目不被允许。
   - 个人解释栏目写作者本人的口吻,不照搬 AI 默认开场白。
   - 每个机制/结论尽量在正文里**夹注引用** `[S1][S2]`,不能只在来源表出现。
   - 策略卡片、交互练习、自测题必须结合概念本身设计,不能放通用题充数。

4. **自检**
   - 按 §6 自检清单逐条核,任一条不过就重写那一栏,不能跳过。
   - 不能伪造引用:链接必须实际打开过;不能编造论文标题 / 作者 / 页码。

5. **交付**
   - 输出一个 `.html` 文件,排版统一为深色主题卡片风(见 §5)。
   - 文件名:小写、英文/拼音、避免空格,例:`agent.html`、`transformer.html`。

## 4. 输出结构(固定栏目,顺序不变)

每份学习资料必须包含:

### 0. 页面头部
- 顶部标签:`GUIDE MODE · SOURCE-TRACED CONCEPT GUIDE`
- 大标题:概念中文名 + 英文/缩写
- 一句有力副标题:点出概念的核心张力或反直觉之处
- 元信息标签行(3 个):对象 / 目标 / 重点
- 生成信息:概念域、生成时间、作者核查、先验假设

### 1. 学习目标 (01 · OBJECTIVE)
- 学完应能回答 3 件事,用动词开头(描述 / 解释 / 区分 / 应用 / 评估)。

### 2. 核心问题 (02 · CORE QUESTION)
- 3–5 个"不懂这个就等于不懂概念"的关键问题。

### 3. 先定义它 (03 · DEFINITION)
- 给出**两个权威定义**(优先一学术一厂商,或两个互补的厂商定义),并说明它们强调的不同侧面。
- 一句话个人解释,把定义翻译成自己的话。
- 每个定义都夹注 `[Sx]`。

### 4. 结构化解释 (04 · MECHANISM)
- 核心机制:分步骤或分组件解释,尽量配**可视化图表**(SVG / 流程图 / 预算条)。
- 与相邻概念的位置:在 AI 工程光谱或技术演进脉络中定位本概念。
- 最新进展:2023 年后的关键研究或产品实践。

### 5. 应用场景 (05 · CASE)
- 至少 1 个具体案例,给出"问题 → 用 X 怎么解 → 边界在哪"三段式。
- 案例必须来自真实产品、论文实验或官方最佳实践,不能凭空捏造。

### 6. 策略卡片 / 最佳实践 (06 · STRATEGIES)
- 以 2×2 或 1×4 卡片网格呈现 4 条可操作策略。
- 每条策略包含:**策略名、一句话解释、适用场景、来源标注**。
- 策略必须来自权威资料或厂商最佳实践,不能是泛泛而谈。

### 7. 概念辨析 & 使用边界 (07 · BOUNDARY)
- 最少 2 条"X 的边界在哪 / X 做不到什么 / X 和 Y 的差异"。
- 用对比表 + 硬边界清单组合呈现。

### 8. 交互练习 (08 · PRACTICE)
- 设计 1 个交互场景,让用户在若干选项中选择正确的上下文/工具/策略组合。
- 选择后给出反馈:为什么对、为什么错、对应哪一条来源。

### 9. 自测题 (09 · QUIZ)
- 3–5 道题:定义、机制、边界/辨析,难度循序渐进。
- 题型可以是选择或简答;选择题必须给出正确选项和解析。

### 10. 参考来源 (10 · SOURCES)
- 表格形式,列:编号 / 类型 / 来源标题 / 链接 / 核查状态(已核 / 仅参考)。
- 编号与正文 `[Sx]` 一一对应。

### 可选附加
- **知识地图**:标出 X 与已学概念的连接关系,放在页面底部。

## 5. 视觉规范(深色主题 Source-Traced Guide)

- 背景 `#0f172a` 系,文字 `#e2e8f0`;强调色用青(`#22d3ee`) / 紫(`#a78bfa`) / 琥珀(`#fbbf24`) 三档,语义区分:
  - 青 = 关键定义 / 结论
  - 紫 = 机制 / 步骤 / 策略
  - 琥珀 = 易错点 / 边界 / 警告
- 每栏一张卡片,圆角 16px、阴影、左侧 4px 色条对应语义色。
- 顶部"GUIDE MODE"标签使用小写字母间距,颜色 muted。
- 章节编号使用 `01 · 英文标签` 格式,例如 `01 · OBJECTIVE`。
- 来源引用使用上标 `[S1]`,颜色与链接一致。
- 策略卡片使用网格布局,卡片带 hover 效果。
- 交互练习使用原生 JS,选项可点击,反馈即时显示,不依赖外部 CDN。
- 代码块用 inline `<code>` 与 `<pre>`,使用等宽字体。
- **HTML 必须可独立打开**(内联 CSS 与 JS,不依赖外网字体 / CDN;若需图标用 emoji 即可)。

## 5.5 文风硬约束(生成时必须遵守)

- **禁用"不是 X,而是 Y"句式**,包括其全部变体:`不是…而是…`、`并不…而是…`、`…而非…`、`不是…而是…`、`X,而不 Y`。
  需要对比两个说法时,改用直述 + 转折,或拆成两句。
  - 反例:`记忆不是上下文本身,而是需要先检索再注入的持久化信息。`
  - 正例:`记忆属于持久化信息,需要先检索再注入上下文,与上下文本身不能画等号。`
- **禁用机械过渡词**:"第一 / 第二 / 第三"、"总之"、"首先…其次…最后"这类靠序号推进段落的写法。段落之间靠因果、转折、递进、并列的语义自然衔接。
- **禁止用破折号连接两个分句**。需要断句就用句号或逗号。
- **外文人名首次出现**用「中文译名(外文原名)」格式,如「希夫曼(Shifman)」;之后只用中文译名。学术引用格式不受此限。
- 交付前对生成的 HTML 全文检索一遍 `不是|而是|而非|而不`,命中必须为 0。

## 6. 自检清单(交付前必跑,过不了不能算交付)

- [ ] 10 个栏目(含页面头部)都有,缺资料时显式写"待补",不删栏目。
- [ ] 每条链接都打开过;无法访问的链接删掉并标注。
- [ ] 没有任何"也许 / 大概 / 应该说"式的兜底;不确定就写"未核验 - 仅作参考"。
- [ ] 应用场景是真实存在的产品或论文,凭空捏造的一律删掉。
- [ ] 概念辨析至少覆盖 1 组常被混淆的相邻概念。
- [ ] 策略卡片 4 条都来自权威资料或最佳实践,有来源标注。
- [ ] 交互练习有明确正确选项和解析,解析能对应到具体来源。
- [ ] 自测题有答案/提示,难度递进。
- [ ] 整篇不含 API Key / 邮箱 / 学号 / 真实姓名等隐私;若用户给了真实姓名,概念卡里用化名或角色"作者"。
- [ ] HTML 在 Chrome / Edge 单文件打开能正常渲染,内联样式无外部依赖。
- [ ] **来源硬约束**:T0 ≥ 2、T1 ≥ 1、2023 年后来源 ≥ 1、Wikipedia ≤ 1;来源表里的"已核"链接确实能打开。
- [ ] **文风硬约束**:全文检索 `不是|而是|而非|而不|并不`,命中数为 0;无"第一/第二/第三""总之"等机械过渡词。
- [ ] 核心术语有至少两个权威定义并对比。
- [ ] **文风合规**:正文里 `不是|而是|而非|而不` 命中数为 0;无"第一/第二/第三""总之"等机械过渡词;外文人名已用「中文译名(外文原名)」。

## 7. 这个 Skill 不做什么

- 不写工程代码、不替你做选型对比。
- 不替你做决策(如"我该学 X 还是 Y"),只把每个概念讲清楚,选型是学习者的事。
- 不生产虚构的论文 / 书籍 / 标准号;查不到就标注"未核验"。
- 不向外部网络暴露任何用户输入(含个人笔记);所有外部抓取只用于资料背景,不写入用户私有区。

## 8. 调用方式

- **在 WorkBuddy 中**: 在项目根目录打开会话,直接说:

## 9. 维护与扩展

- 每对一个概念跑过本 Skill,若发现某个栏目总是空或总是重复,改动优先落在 Skill 身上,卡片次之。
- 自检清单每学期回顾一次,补上"AI 幻觉"的最新套路。
- 不要把私有资料上传到 Skill 目录;`.gitignore` 已屏蔽 `.workbuddy/concept-sources/`。
