# learn-concept · 个人概念学习资料生成 Skill

## 1. 这个 Skill 解决什么问题

把"我想学 X,但不知道从哪入手、哪些是真、哪些是 AI 编的"这个问题流程化。
- 我帮你定一套**固定的卡片结构**(七个固定栏目),让任何概念都变成可比对、可复习、可拼图的形式。
- 我帮你按栏目**检索与组织资料**,但所有外链都必须可点击且来自权威源;我会标注哪些是已核查、哪些是参考级。
- 我把**易混淆点**和**使用边界**当一等公民处理,避免"读完感觉懂了,实际分不清 X / Y / Z"。

## 2. 输入

调用方需向 Skill 提供以下信息(尽量一次给齐,缺什么我会问):

| 字段              | 必填 | 说明                                                              |
| ----------------- | ---- | ----------------------------------------------------------------- |
| `concept`         | 是   | 待学概念的标准中文名,必要时附英文/缩写                          |
| `known`           | 否   | 学习者已有的先验(0 / 入门 / 已了解相邻概念)                     |
| `goal`            | 否   | 学习目标(面试 / 写代码 / 写论文 / 和别人讲清……)                 |
| `deadline`        | 否   | 截止时间,影响卡片深度                                            |
| `preferred_form`  | 否   | 输出形态:HTML 卡片(默认)/ Markdown 摘要 / 极简一句话              |
| `extra_context`   | 否   | 一段课程讲义、论文摘要、官方文档片段等;若不提供则全靠模型常识  |

可被其他流程复用:传入 `concept` 字符串即可重跑,无需修改 Skill 本体。

## 2.5 资料来源标准(硬性)

### 2.5.1 来源分级

| 等级 | 性质 | 典型来源 | 使用方式 |
|------|------|----------|----------|
| **T0 一手 / 学术** | 同行评审论文、arXiv 预印本(作者来自知名机构)、会议论文集(NeurIPS/ICML/ICLR/ACL/EMNLP)、官方标准文档 | arxiv.org/abs/xxx、ACL Anthology、IEEE、ACM、OpenAI/Anthropic/Google 官方技术报告 | 优先引用,用于支撑核心机制、关键结论和数字 |
| **T1 权威转述** | 厂商官方文档、厂商工程博客、知名研究机构博客、权威书籍 / 教材章节 | docs.anthropic.com、openai.com/research、research.google、distill.pub、Lilian Weng 博客 | 用于解释工程实践、产品形态、官方定义 |
| **T2 背景佐证** | 维基百科、科普文章、社区总结 | wikipedia.org、medium/掘金等技术社区 | 仅用于辅助理解,**不能**替代 T0/T1 作为核心来源 |

### 2.5.2 最低数量与质量要求

每份概念卡片必须满足:
- **≥ 2 个 T0 来源**(至少一篇支撑核心机制,一篇支撑边界/对比/最新进展)。
- **≥ 1 个 T1 来源**(官方文档或厂商/研究机构的权威解读)。
- **≥ 1 个 2023 年及以后的来源**(对 AI 类概念,确保内容不过时;若是经典理论如 CAP/Transformer 可放宽,但需说明)。
- 总来源数建议 5–8 条;Wikipedia 最多 1 条,且只能标 T2。

### 2.5.3 推荐检索路径

按优先级依次查:
1. **arXiv**:`https://arxiv.org/search/?query=<英文概念>&searchtype=all&source=header&order=-announced_date_first`
2. **ACL Anthology**:适用于 NLP / LLM 相关概念
3. **Google Scholar**:找高被引论文和最新综述
4. **厂商官方文档 / 研究博客**:Anthropic、OpenAI、Google DeepMind、Microsoft Research
5. **GitHub 官方仓库 / 论文实现**:验证方法是否存在
6. **source-tracer skill**(若可用):自动追溯原始出处

## 3. 工作流程(Skill 被调用后必须按序执行)

1. **拆解输入**
   - 把概念拆成 3–5 个"如果不懂这些就看不懂 X"的子问题(下文称 §2 核心问题)。
   - 若 `known` 给出"入门",跳过基础解释,直入差异与边界。

2. **查证与建源**
   - 对每个子问题,优先按 §2.5 的 T0 → T1 → T2 顺序找来源。
   - **不能引用二手博客当一手源**;Wikipedia / 官方文档 / arXiv 摘要 / 标准组织页面 才可作 T0。
   - 对 AI 类概念,必须找到 2023 年后的进展(长上下文、新架构、产品化实践等),不能只停留在 2022 年甚至更早。
   - 实在查不到时,在卡片里**显式标注"未核验 - 仅作背景"**而不是装作权威。

3. **组织输出**
   - 按 §4 的 7 个栏目生成,**栏目顺序固定**;任何栏目都不能省,缺资料时写"待补 - 来源缺失"而非删栏目。
   - 个人解释栏目写作者本人的口吻,不照搬 AI 默认开场白。
   - 每个机制/结论尽量在正文里**夹注引用**<sup>[1][2]</sup>,不能只在来源表出现。

4. **自检**
   - 按 §6 自检清单逐条核,任一条不过就重写那一栏,不能跳过。
   - 不能伪造引用:链接必须实际打开过;不能编造论文标题 / 作者 / 页码。

5. **交付**
   - 输出一个 `.html` 文件,排版统一为深色主题卡片风(见 §5)。
   - 文件名:小写、英文/拼音、避免空格,例:`agent.html`、`transformer.html`。

## 4. 输出结构(7 个固定栏目,顺序不变)

每份学习资料必须包含:

1. **学习目标** — 学完应能回答 3 件事,用动词开头(描述 / 解释 / 区分 / 应用)。
2. **核心问题** — 3–5 个"不懂这个就等于不懂概念"的关键问题。
3. **结构化解释** — 用三层结构:一句话定义 → 核心机制(可分步骤/可画图)→ 与相邻概念的位置。
4. **应用场景** — 至少 1 个具体案例,给出"问题 → 用 X 怎么解 → 边界在哪"三段式。
5. **概念辨析 / 使用边界** — 最少 2 条"什么不是 X / X 不能做 / X 和 Y 的差异"。
6. **自测题** — 3 道题:1 道定义、1 道机制、1 道边界/辨析;难度循序渐进。
7. **参考来源** — 表格形式,列:来源类型 / 来源标题 / 链接 / 核查状态(已核 / 仅参考)。

可选附加(若上下文允许,加分项):**一段知识地图**:标出 X 与已学概念的连接关系,放在页面底部。

## 5. 视觉规范(深色主题卡片)

- 背景 `#0f172a` 系,文字 `#e2e8f0`;强调色用青(`#22d3ee`) / 紫(`#a78bfa`) / 琥珀(`#fbbf24`) 三档,语义区分:
  - 青 = 关键定义
  - 紫 = 机制/步骤
  - 琥珀 = 易错点/边界
- 每栏一张卡片,圆角 16px、阴影、左侧 4px 色条对应语义色。
- 代码块用 inline `<code>` 与 `<pre>`,使用等宽字体。
- **HTML 必须可独立打开**(内联 CSS,不依赖外网字体 / CDN;若需图标用 emoji 即可)。

## 6. 自检清单(交付前必跑,过不了不能算交付)

- [ ] 7 个栏目都有,缺资料时显式写"待补",不删栏目。
- [ ] 每条链接都打开过;无法访问的链接删掉并标注。
- [ ] 没有任何"也许 / 大概 / 应该说"式的兜底;不确定就写"未核验 - 仅作参考"。
- [ ] 应用场景是真实存在的产品或论文,不是凭空捏造。
- [ ] 概念辨析至少覆盖 1 组常被混淆的相邻概念。
- [ ] 整篇不含 API Key / 邮箱 / 学号 / 真实姓名等隐私;若用户给了真实姓名,概念卡里用化名或角色"作者"。
- [ ] HTML 在 Chrome / Edge 单文件打开能正常渲染,内联样式无外部依赖。
- [ ] **来源硬约束**:T0 ≥ 2、T1 ≥ 1、2023 年后来源 ≥ 1、Wikipedia ≤ 1;来源表里的"已核"链接确实能打开。

## 7. 这个 Skill 不做什么

- 不写工程代码、不替你做选型对比。
- 不替你做决策(如"我该学 X 还是 Y"),只把每个概念讲清楚,选型是学习者的事。
- 不生产虚构的论文 / 书籍 / 标准号;查不到就标注"未核验"。
- 不向外部网络暴露任何用户输入(含个人笔记);所有外部抓取只用于资料背景,不写入用户私有区。

## 8. 调用方式

- **在 WorkBuddy 中**: 在项目根目录打开会话,直接说:

- **单独复用**: 把 `concept="Transformer"` 当参数传给我即可,无需修改本文件。
- **跨项目复用**: 此 Skill 是项目级 Skill,跟随仓库走;不同仓库可拷贝此 `SKILL.md` 复用,也可在 USER 级 Skill 里登记一份只读模板。

## 9. 维护与扩展

- 每对一个概念跑过本 Skill,若发现某个栏目总是空或总是重复,优先改 Skill 而不是改卡片。
- 自检清单每学期回顾一次,补上"AI 幻觉"的最新套路。
- 不要把私有资料上传到 Skill 目录;`.gitignore` 已屏蔽 `.workbuddy/concept-sources/`。
