3. 结构化解释 STRUCTURED

一句话定义

Agent 是 以大语言模型为认知核心,通过循环"推理—行动—观察"调用外部工具以达成目标的自主系统。它不只是"回答",而是在一个开放环境中"把事情做完"。[1][4]

核心机制:ReAct 循环

① Reason读任务与历史,决定是否需要工具、用哪个工具
② Act调用一个工具(检索/计算/API)
③ Observe读回结果,更新对世界状态的理解
④ Decide判断目标是否达成;未达成则继续循环
⑤ Answer整合工具结果,给出最终响应

Yao 等人在 2022 年的 ReAct 论文中首次系统地把"推理轨迹(Thought)"和"行动轨迹(Action)"交错在一个统一的文本序列里,让模型在每一步自己决定是继续推理还是调用工具。[1] 与一次性 Chain-of-Thought 不同,ReAct 允许模型在推理过程中主动修正:如果检索返回为空,它会在下一轮换一种检索策略。

三块组成

  • 大脑(Brain):LLM 负责规划、推理和决策。它本身只输出文本,不直接改变世界。
  • 工具(Tools):函数、API、搜索引擎、代码解释器等,让 Agent 获得当前模型权重里不存在的信息或能力。Schick 等 2023 年的 Toolformer 证明语言模型可以自学何时调用工具。[2]
  • 记忆(Memory):短期记忆是当前会话的上下文,长期记忆是向量库、数据库或外部摘要。Wang 等的 2023 年综述把"记忆"列为 Agent 三大核心模块之一。[3]

Agent 在 AI 工程光谱中的位置

从"单次模型调用"到"完整 Agent"是一个自主性递增的光谱:单次调用没有循环,Workflow 是预先写死的循环,Agent 是模型自己决定何时循环、循环到哪一步。[4]

4. 应用场景 CASE

场景:学术研究助理 Agent 需要根据用户问题"找到最近 3 年关于长上下文 LLM 的 5 篇高被引论文,并给出方法对比表"。

Agent 怎么解:
  1. Reason:目标需要外部学术数据库,无法凭空编造 → 调用 Google Scholar / Semantic Scholar API。
  2. Act:调用搜索工具 `search_papers("long-context LLM", years=3, top=10)`。
  3. Observe:得到 10 篇候选论文,含标题、摘要、被引次数。
  4. Reason:需要按被引次数排序并提取方法关键词 → 调用解析工具。
  5. Act:调用 `extract_methods(paper_list)`。
  6. Answer:生成对比表格,并为每篇给出可信度判断。
边界:Agent 只能基于工具返回的事实回答;如果搜索 API 漏掉重要论文,Agent 不会知道,只能提示"检索结果有限"。
来源:类似能力在 ReAct 问答实验[1]和 Toolformer 工具调用实验[2]中已被验证。

5. 概念辨析 & 使用边界 BOUNDARY

对比项普通 LLM 调用WorkflowAgent
目标回答单次问题完成预先定义的多步流程完成目标,路径由模型决定
循环控制无人写死模型自己决定循环次数
工具可选可选通常必需
失败模式幻觉边界外输入导致崩溃循环死锁、工具错用、累积性错误
最优场景封闭问题流程稳定、可枚举目标明确但路径开放
三条硬边界:
  1. 不要把开放性目标交给 Agent:"让公司今年活得更好"缺乏明确的完成条件,Agent 会自循环到耗尽预算。
  2. 不要让 Agent 在没有护栏的情况下调用付费/不可逆操作:"下单""转账""发邮件"等动作必须有人类确认或回滚机制。
  3. 不要把记忆和上下文混为一谈:上下文是本次推理的输入窗口,记忆是跨会话检索回来的外部信息。[3]

6. 自测题 QUIZ

  1. (定义) 用一句话区分 Agent 与 Chatbot,并给出判定标准。
    提示判定标准 = 是否能自主决定调用工具并在多步循环中追求目标。
  2. (机制) 解释 ReAct 为什么把"思考"和"行动"放在同一个序列里,而不是先全部推理再全部行动。
    提示因为模型需要根据行动结果(观察)调整下一步推理;分开会失去反馈修正能力。[1]
  3. (边界) 给出 1 个不该用 Agent 的真实场景,并说明应该用什么替代。
    提示例:"把这段中文翻译成英文"用单次 LLM 调用即可;上 Agent 会引入不可控和成本,无收益。
