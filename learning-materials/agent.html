2. 核心问题 CORE QUESTION

  1. Agent 和 Chatbot 到底差在哪?
  2. 它"做事"靠的是模型本身,还是靠循环?
  3. 工具调用(Tool Use)在 Agent 里扮演什么角色?
  4. Agent 的"记忆"和"上下文"是同一回事吗?
  5. 为什么不能所有任务都丢给 Agent?

3. 结构化解释 STRUCTURED

一句话定义

Agent 是一类 能自主规划、并通过工具与外部世界交互以完成目标 的 LLM 系统。它不止于"回答",而是"把事情做完"。

核心机制:ReAct 循环

① Reason读任务,决定是否需要拆解/查资料/调工具
② Act调一个工具(查网页/读文件/调用 API)
③ Observe读回结果,判断是否要继续循环
④ Decide下一步是再来一次,还是收尾
⑤ Answer把工具结果拼成最终答复

ReAct(Reason + Act)是 2022 年 Yao 等人提出的范式,论文把"思考"和"行动"交错写进同一个 prompt,模型在每一轮决定是输出想法还是工具调用。[1][3]

三块组成

  • 大脑:LLM 负责推理与规划。
  • 双手:工具层 —— 函数调用、浏览器、文件系统、SQL、知识库。
  • 记忆:短期(当前会话上下文)+ 长期(向量库 / 数据库),决定 Agent 是否"认识你"。

4. 应用场景 CASE

场景:让你电脑里的 AI 助手帮你订一张今晚 9 点上海到北京最便宜的航班。

Agent 怎么解:
  1. Reason:任务可能要查实时航班 → 必须调用搜索/航班 API,不能凭空编。
  2. Act:调用航班工具 `search_flight(SHA,PEK,2026-09-08T21:00)`。
  3. Observe:拿到 10 条结果,挑出 3 条低于均价的。
  4. Reason:用户没给价格偏好 → 主动追问 / 给三档推荐。
  5. Act:再调 `book_flight(flight_id,user_info)` 完成下单。
边界:如果工具 API 不支持退款、改签,Agent 也只能"告诉你它做不到",不能伪造结果。

OpenAI 于 2025 年初上线的 Operator 就是这类 Agent 的产品形态。[4]

5. 概念辨析 & 使用边界 BOUNDARY

对比项普通 LLM 调用Agent
目标回答单次问题完成多步任务
工具默认无可注册多个工具,按需调用
循环一轮即结束Reason→Act→Observe 反复
失败模式幻觉幻觉 + 循环死锁 + 工具报错传染
三条硬边界:
  1. 不要给 Agent 写开放型目标:"让公司今年活得更好" — 没有明确达成条件,Agent 会自循环到耗尽预算。
  2. 不要让 Agent 自己决定要不要调用付费 API:把"是否花钱"留给人类把关。
  3. 不要把记忆当成上下文:长期记忆是检索 + 摘要后的片段,不是历史会话原文。

6. 自测题 QUIZ

  1. (定义) 用一句话区分 Agent 与 Chatbot,并给出判定标准。
    提示 判定标准 = 是否能自主选择并调用工具以完成多步目标。
  2. (机制) 描述 ReAct 循环里 Reason 与 Act 的最小切换规则,并解释"思考为什么不放在外部脚本里"。
    提示 模型自己决定何时停止思考、改成工具调用;放外部脚本会丢失对当前上下文的判断。
  3. (边界) 给出 1 个不该用 Agent 的真实场景,并说明应该用什么替代。
    提示 例:"把这段中文翻译成英文" — 用单次 LLM 调用即可;上 Agent 是过度工程,徒增成本与不可控。
